# MCP setup inventory

The session top bar's **Inspect setup** opens a read-only inventory of MCP configuration. It does not start a server, connect to an endpoint, invoke Claude, inspect live tools/prompts or handle authentication. For live status and authorization use `/mcp` in the local Claude Code terminal. Entries are configured declarations, not proof they loaded or are connected, enabled, approved, or authenticated. Managed policy and effective precedence are not evaluated; duplicate names retain their separate scopes.

Sources: top-level `mcpServers` and the exact session-cwd `projects[cwd].mcpServers` in `~/.claude.json` (user and local); when `CLAUDE_CONFIG_DIR` is set, `.claude.json` inside that directory instead; and `.mcp.json` directly in the session cwd (project). These locations are documented by [Claude Code MCP quickstart](https://code.claude.com/docs/en/mcp-quickstart). Git root discovery, ancestor files, plugins, managed settings, cloud connectors and project enable/disable settings are not inspected, so absence is not proof of absence in Claude. Local entries keyed by a different project-root spelling are not found.

Only names (bounded and stripped of unsafe control characters by rejection), scope and a whitelisted transport kind leave the backend. Command, arguments, environment, headers, URLs and credentials are never sent or logged. A missing type with a command field is classified as stdio; other unknown types remain unknown. Each fixed file must be a regular single-link file, at most 1 MiB, not a symlink, and is checked before and after opening. Project reads are confined to the resolved session directory; user reads are limited to the documented config file under its selected root. Missing and unreadable sources are distinct; malformed, oversized and unsafe files are unreadable. Malformed relevant nested maps or entries mark the inventory incomplete while preserving readable entries. Up to 150 entries are returned, with a scan deadline and concurrent-read limits. As with ordinary filesystem path checks, this is not an OS sandbox against a concurrently malicious local process; metadata cannot establish effective runtime policy. Names themselves are user-controlled and may contain sensitive text.

Inventory requests are not buffered offline. An early request rejected before the session subscription attaches waits for that session's history marker and retries; a timeout or other error offers manual Refresh.
