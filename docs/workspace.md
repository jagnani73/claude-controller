# Session Workspace: read-only Files and Changes

The session top bar opens a lazy-loaded Workspace sheet. It covers the full phone width and up to 1,100px on desktop. Chat, composer and queue stay mounted underneath; changing tabs or viewport does not replace SessionView. This feature never sends a Claude prompt or restarts its PTY.

## Views

- **Files:** browse only the session cwd, with breadcrumbs and a parent button. Directory pages contain up to 200 entries; each request scans at most 10,000 entries, without recursion. Sorting is within each page, not a global directory snapshot. Concurrent filesystem changes may shift pages; Refresh rereads them.
- **Source:** numbered text, a small lexical syntax highlighter for common source extensions, optional wrapping, relative-path copy. All content is React text, never executed, HTML-previewed or inserted as markup. Up to 256 KiB / 4,000 lines are read, served in 400-line pages with an explicit truncation notice. NUL-containing or invalid UTF-8 content is marked binary/non-UTF-8.
- **Changes:** explicitly workspace-wide, not attributed to Claude. Staged, unstaged and untracked entries are separate. Staged compares HEAD to index, unstaged compares index to working bytes, untracked compares empty to working bytes. Renames retain the old path when it is inside cwd; deletions compare to empty. Conflicts, symlinks, submodules, binary and large files are unavailable rather than misleading partial diffs.
- **Diff:** unified on phones; side-by-side by default on desktop, with a unified toggle. Three-line context by default, full-context toggle, at most 300 rendered rows per page. Line numbers preserve the original positions. A bounded LCS uses a replacement block (explicitly labeled) if a changed region would exceed one million cells. Diff text is raw source; Git textconv and clean filters are intentionally not applied. Filtered files can therefore look different from a configured Git CLI diff. Large-file comparisons are withheld rather than displayed as complete.
- Refresh is explicit. Empty, not-Git, loading, unavailable, disconnected and retry states are distinct. There are no edit, stage, revert or commit actions.

## Protocol and boundaries

`packages/common/src/workspace-types.ts` is re-exported through `common/types` (and therefore `common`). `workspace_request` carries `requestId`, `sessionId` and a `list`, `file`, `changes` or `diff` query. `workspace_response` echoes both identifiers and returns a discriminated result or error. `ws.service.ts` adds only a dispatcher case; the implementation is in three focused `workspace*.service.ts` services.

The backend derives cwd from SessionManager or a known session transcript, never from a client root. Requests validate every shape/offset/area. Slash-separated relative paths reject traversal, absolute/drive/UNC paths, backslashes, Windows ADS, reserved device names and .git internals. `path.relative` containment and `realpath` checks apply at every existing component, including paths returned by Git and missing/deleted paths' parents. Symlinks/junctions are deliberately not followed, even inside the root; a dangling link is not treated as a missing ordinary file. File descriptors are checked against the revalidated path before reading. Like portable Node path checks generally, these are not an OS capability sandbox against a malicious local process continuously swapping filesystem objects.

Git is called with `execFile` argv (no shell), literal pathspecs, 8-second command timeouts and 2 MiB output caps. Inherited GIT_* overrides are removed (case-insensitively). Optional locks, hooks, fsmonitor, untracked-cache writes, external diff and configured filter drivers are disabled. Status uses NUL-delimited porcelain; tree/index lookups use NUL delimiters and raw blob IDs. No `git diff`/textconv or user executable is used. The index is not refreshed on disk. Cwd inside a larger repository is scoped to its subtree; cross-boundary old rename paths are not disclosed. Filenames unsupported by the canonical path contract are omitted; invalid UTF-8 Git filenames cause an honest read failure, never lossy path lookup.

Executable discovery never uses the session cwd or PATH (even an absolute PATH entry can name a hostile repository). Windows defaults search Git's cmd/bin/mingw bin locations under the operator environment's ProgramW6432/ProgramFiles/ProgramFiles(x86) installation roots. POSIX defaults search /usr/bin, /bin, /usr/local/bin and /opt/homebrew/bin. The file is canonicalized, must remain in its trusted installation root, must be a regular executable native binary (Windows .exe plus MZ header; POSIX ELF/Mach-O header), and is cached for the backend lifetime. Discovery does not execute candidates. Scripts/batch wrappers are not supported. Missing Git produces an explicit sanitized unavailable error, not a non-Git workspace result.

For other installations the backend operator can set `GIT_BIN` to an absolute native Git executable. This is an explicit trust grant to that executable and its installation directory, not a client/session option; an invalid override fails closed without fallback. The backend startup environment (including installation roots), system installation directories and any configured override must be controlled by the operator, not a repository or agent. Native-header checks reject accidental scripts, not malicious native code: executable integrity and local-administrator compromise are outside this boundary. Restart after changing the binary or configuration.

Four requests per socket and sixteen globally may run concurrently. The frontend issues only while connected, correlates request/session/socket generation, ignores stale replies, auto-reads on reconnection, and removes response listeners and the 45-second timeout on navigation/close. Errors from OS/Git are sanitized to avoid disclosing paths beyond cwd. Reads are snapshots, not a transactional Git view; files can change while the user is looking, and Refresh is the reconciliation mechanism.

## Terminal integration

`WorkspacePanel` accepts `terminal?: ReactNode`. Supplying it enables the Terminal tab and renders it only while that tab is selected. The parent can lazy-import `components/workspace/TerminalPanel.tsx` and pass a Suspense-wrapped element using the session ID. No terminal service, terminal dependency, or shell write action is part of this Files/Changes patch. Terminal lifecycle and reconnect behavior remain that component's responsibility.

Tool-card path linking is intentionally deferred: existing tool inputs can name absolute/outside-workspace paths and have varying shapes. A future link should first normalize to the selected session's relative path and still use the same backend containment checks, never broaden file-read authority.

## Verification and threat assumptions

The transport/session trust model is unchanged: Tailscale/Caddy provide access control and the backend's known session cwd is authoritative. The new surface treats client request fields and workspace filenames/content as untrusted. It does not grant arbitrary filesystem roots. It is not a sandbox against a hostile local process racing filesystem or Git configuration updates. The independent security review should examine those reachable boundaries rather than infer an additional authentication system.

A temporary Windows fixture exercised spaces/Unicode/literal bracket filenames, malformed types, traversal/absolute/UNC/ADS paths, sibling-prefix rejection, .git hiding, junction escapes (including paths reported by Git), binary/large files, file and directory pagination, staged/unstaged/untracked/rename/delete, a Git subdirectory, an unborn branch and not-Git state. Configured clean/process filters, external diff, textconv, pager and fsmonitor commands were tripwires. Hashes of every fixture file including .git/index/config before and after reads matched, and no tripwire artifact appeared. 150 generated diff pairs reconstructed both originals. The temporary fixture was removed rather than adding a test file.

Executable-resolution follow-up: a temporary Windows fixture compiled a native repository-local `git.exe` that writes a sentinel, confirmed that it fires when deliberately executed, then put that repository first on PATH (also including empty and relative entries). Fresh discovery selected `C:\Program Files\Git\cmd\git.exe`; Changes and staged/unstaged/untracked diffs succeeded without the sentinel. All fixture file hashes, including Git metadata, remained unchanged across reads. Invalid `GIT_BIN` produced an explicit sanitized unavailable response. The temporary harness and fixture were removed, not retained as tests.

Conflict follow-up: all porcelain unmerged combinations (`DD AU UD UA DU AA UU`) are classified before splitting staged/unstaged entries, and both entries retain status `U`. Either diff area returns the conflict-unavailable notice without ordinary deletion/addition content. A real rename/rename merge produced `DD` and a content merge produced `UU`; additional unmerged index-stage fixtures exercised all seven combinations.

The original existing suite passed (117 tests / 13 files). Browser visual verification was not completed: the preview server started, but browser attachment was denied or ownership changed. No desktop/mobile visual-pass claim is made. Parent integration should smoke-test Files/Changes, reconnect/navigation correlation, and draft retention at both widths before release.
