# Command and skill discovery

## Verification scope

Temporary filesystem fixtures exercised user/project metadata, empty scalar fields, comments, non-user-invocable skills, oversized files, hard-link rejection, an outside-directory junction, and suppression of skill bodies from responses. Shared-policy assertions covered representative blocked transitions/pickers, explicit model/effort forms, plain text and unknown custom commands.

A temporary harness mounted the actual composer and WebSocket listener/rejection store in isolated headless Chrome with a synthetic catalog. All 21 cases passed: catalog selection without execution, second-Enter send, native-form submission, blocked text retained, IME Enter, Shift+Tab, session isolation, recovery without a mounted input, clipboard failure, explicit restore, offline/reconnect behavior, timeout/Retry, bounded-history warning, and four viewport sizes (320×568, 390×844, 768×320, 1280×800). This checks UI state, not end-to-end CLI command execution or installed capability availability. No Claude prompt was sent; temporary fixtures were deleted.

## Behavior and boundaries

The composer offers a bounded prefix picker. Selecting a row inserts text into the draft; it does not execute it. Enter or Tab selects a highlighted row; a subsequent Enter sends. Shift+Tab moves focus and Escape dismisses the picker. The picker uses the current session's catalog, requests it without offline buffering, and offers Retry after errors or an eight-second timeout; reconnect subscription retries it while a slash draft is open. The docs-based built-in suggestions are not an installed-command inventory. File discoveries are not proof that Claude loaded or permits a skill. Plugins, MCP commands, nested legacy command namespaces, managed settings and effective configuration are not catalogued.

A server-rejected command is retained in memory even if the composer is hidden or the user has navigated away. Return to that session to explicitly restore it (replacing the draft), copy it, or dismiss it; nothing is resent automatically. Recovery retains up to five outcomes per session, for up to 20 sessions, with command text capped at 32,768 characters and a truncation notice. The UI explains the limits and warns when oldest entries are removed; it is not a durable command archive and does not survive a page reload. Clipboard failure is shown with a manual restore/copy alternative.

The server uses the subscribed session's configured cwd, never a client-supplied root. It streams direct children of `.claude/skills` and `.claude/commands` in that project and in `CLAUDE_CONFIG_DIR` (or `~/.claude` when unset). Only simple scalar frontmatter name, description, argument-hint and user-invocable fields are interpreted; empty fields cannot consume the following line, and multiline YAML values are not interpreted. Bodies are not returned or executed. Symlink targets must remain within the relevant root, hard links are rejected, and files are bounded to 16 KiB. Opened file identity and canonical paths are rechecked; ancestor-directory replacement is still a local-filesystem race limitation, not an OS sandbox.

The combined catalog has a 150-entry cap (including docs suggestions), directory scans stop after 150 examined entries each, and a two-second work deadline stops further discovery between filesystem calls. The deadline cannot cancel a filesystem operation already in progress. Per-socket requests are single-flight and spaced, with bounded send-buffer checks. Missing paths are normal; unreadable/unsafe/oversized scopes produce warnings rather than silently claiming complete discovery. Duplicates are displayed with their source and scope, not resolved as effective precedence.

The shared dispatch policy blocks known session/cwd-changing commands and unrepresented picker/actions before respawn or PTY input. Explicit `/model <alias>` and `/effort <level>` retain the existing app interception. Other commands are inherited and unverified; they may cause side effects or open an invisible CLI dialog. Use the local CLI if recovery is required. The policy recognizes leading slash tokens only; it does not parse shell commands or constrain ordinary prompts or model tool use. Blocked composer text stays editable; a server-side slash rejection offers restoration. No CLI behavior or installed availability was verified by this feature.
